The desktop drivers share the existing TypeScript runner, locators, assertions and
reports. Application language and driver language are independent: Python AT-SPI
inspects Linux accessible controls, C# UI Automation inspects Windows controls,
and Rust AX inspects macOS controls. The C++ Qt helper provides the cooperative
Qt Widgets/Quick path.

## Platform profiles

| Profile | Required host | Status |
| --- | --- | --- |
| `qt()` | Matching Qt 6 kit | Offscreen tests cover selected Widgets/Quick controls. |
| `desktop({ backend: 'linux-atspi', executable, args })` | Linux accessibility/D-Bus session | Experimental; run the real GTK fixture to qualify the host. |
| `desktop({ backend: 'windows-uia', executable })` | Windows interactive desktop | Experimental; compile and run the WPF fixture on Windows. |
| `desktop({ backend: 'macos-ax', executable })` | macOS with Accessibility permission | Experimental; compile and run the AppKit fixture on macOS. |

The OS sidecar executable is configured separately from the application's `appPath`.
It receives the target executable and arguments as literal argv, launches the target,
and scopes inspection to its process. It does not attach to arbitrary running apps.
See the repository's `DESKTOP.md` and `native/<backend>/README.md` for installation
commands, capability lists and native qualification scripts.

All native targets, including Qt, share the runner's `local-desktop` exclusive
resource. Within one run, only one native worker can own the desktop at a time,
and its cleanup completes before another native target starts. Separate runner
processes still require separate desktop sessions or external serialization.

## Accessible behavior

Control patterns must support the requested action. A missing pattern produces an
explicit unsupported-capability error. Observe and assert the state after actions;
an accepted invocation does not establish business success. Password values are
suppressed before serialization. Bounded trees declare truncation.

OS providers support readonly actionability preflight and `scrollIntoView` for
controls exposing the required platform interface. Preflight can be polled;
mutating actions are dispatched once and are not replayed after an uncertain
outcome. AX selection requires writable `AXSelectedChildren` and one matching
direct child. AX nodes with unknown visibility cannot satisfy positive or negated
visibility assertions. These semantic checks do not prove screen occlusion.
Missing AX enabled/focused state is also explicitly unknown and cannot satisfy
positive or negated assertions for that state.

Windows selection preflight resolves the requested realized option and rejects
missing, disabled or ambiguous matches without changing the UI. Open a collapsed
popup explicitly before selecting an option its provider has not exposed.
Qt scrolling succeeds only when the target center is visible in its supported
container hierarchy. Unsupported clipping fails; an uncertain post-scroll result
is not retried. Already-visible controls need no scroll.

Linux and macOS retain observed password sensitivity for each control identity,
including after a reveal toggle. Such controls retain their password purpose
and never expose their content through a later nonsecure snapshot.

Qt adds owned-window enumeration/activation, selected model/view item mappings
and a public C++ `ControlAdapter` source extension. Custom adapters disable helper
screenshots and require `qt({ screenshots: false })`. They must be rebuilt and
qualified with the application's Qt/compiler kit.

The new OS backends do not advertise screenshots or global keyboard input. They
also do not promise clipboard, drag/drop, IME, custom-painted controls, native/DOM
context switching or every toolkit version. A fake-provider contract test does not
count as native desktop qualification. Native video, visual-diff assertions and
arbitrary custom canvases remain absent. New Windows/macOS/Linux Qt workflow
definitions do not establish completed qualification. Check `RELEASE_STATUS.md`
before release.

Tests use TypeScript/JavaScript or the documented C++ authoring bridge connected
to the shared runner. Python, C# and Rust authoring SDKs are not included;
applications in those languages use the shared TypeScript test API.
