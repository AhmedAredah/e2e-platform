---
title: Telemetry
description: The fork CLI has no telemetry destination and sends no usage events.
---

The `e2e-cpp` CLI does not collect or send usage telemetry. The upstream
project's destination and ingestion key have been removed. This applies to
normal commands, CI and model-free runs.

```bash
npx --no-install e2e-cpp telemetry
```

The command reports `Status: disabled (this fork has no telemetry destination)`.
The inherited `enable` and `disable` commands save a local compatibility
preference; neither configures a transport. `E2E_TELEMETRY_DISABLED=1` and
`DO_NOT_TRACK=1` remain recognized opt-out flags. `E2E_TELEMETRY_DEBUG=1` does
not activate collection or sending.

The retained internal event/transport modules are covered by tests with an
explicit mock destination. They are not a public telemetry configuration API.
Adding telemetry to a future distribution requires a deliberate code and policy
change, a destination controlled by its maintainer, and an appropriate user choice.

Telemetry being disabled does not disable configured model providers, app traffic,
HTTP tests, browser downloads or custom reporters. Use `modelPolicy: 'forbid'` or
`--no-model` to prohibit runner model calls, and provision dependencies before
working offline. See the source repository's `SECURITY.md` for trust boundaries.
