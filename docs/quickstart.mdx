title: Quickstart
description: Run your first web or mobile test, then add AI with your own subscription or API key.
---

<Note>
This is the MIT-based e2e-cpp fork. Install the local checksummed kit from the
source archive before using the commands below; the fork package names are not
published by this archive. The browser/mobile presets also need locally packed
engine modules. C++ setup is described in [C++ applications](/cpp).
</Note>


Set up a test, run it, then let an agent drive a flow. Agent steps can use
your own ChatGPT, GitHub Copilot, or SuperGrok subscription, an API key, or a
local model.

<Note>
Use Node.js 22.22.3+ in the 22.x line, or 24.8.0+. On Windows, run inside WSL. Mobile tests also
need Xcode with an iOS simulator runtime, or the Android SDK with an emulator.
</Note>

## Run your first test

<Steps>
  <Step title="Create the test project">
  In your app's directory:

  <CodeGroup>
  ```bash npm
  npx --no-install e2e-cpp init
  ```

  ```bash pnpm
  pnpm exec e2e-cpp init
  ```

  ```bash bun
  bun run e2e-cpp init
  ```
  </CodeGroup>

  Choose **Web (Playwright)** or **Mobile (iOS/Android)**, then choose your
  subscription or model provider. Choose **None** if you only want tests
  without AI. The wizard writes a config and example test, adds dependencies,
  and offers to set up your coding agent. Existing config and test files stay intact.

  <Tabs>
    <Tab title="Web">
    Start your app's dev server at `http://localhost:3000`, or set its address
    in `e2e.config.ts`. You can also [let e2e start it](/starting-your-app).

    <Accordion title="Example web config and test">
    This config uses Vercel AI Gateway. The wizard configures the provider you chose.

```ts title="e2e.config.ts"
import type { E2EConfig } from '@e2e-cpp/core';
import { createAgent } from '@e2e-cpp/core/agent';
import { playwright } from '@e2e-cpp/playwright';
import { gateway } from 'ai';

export default {
  agents: { default: createAgent({ model: gateway('openai/gpt-5.6-luna') }) },
  targets: [{ engine: playwright({ url: 'http://localhost:3000' }) }],
} satisfies E2EConfig;
```

```ts title="tests/example.e2e.ts"
import { test } from '@e2e-cpp/playwright';
import { expect } from '@e2e-cpp/core';

test('app opens', async ({ app, web }) => {
  await app.open('/');
  await expect(web.locator('body')).toBeVisible();
});
```
    </Accordion>
    </Tab>
    <Tab title="Mobile">
    Run `npx agent-device doctor` to check your setup. The example opens
    Settings so you can try it before installing your own app. The wizard
    chooses iOS on macOS and Android elsewhere.

    <Accordion title="Example iOS config and test">
    This config uses Vercel AI Gateway. For Android, the wizard sets
    `platform: 'android'` and `app: 'com.android.settings'`.

```ts title="e2e.config.ts"
import type { E2EConfig } from '@e2e-cpp/core';
import { createAgent } from '@e2e-cpp/core/agent';
import { agentDevice } from '@e2e-cpp/agent-device';
import { gateway } from 'ai';

export default {
  agents: { default: createAgent({ model: gateway('openai/gpt-5.6-luna') }) },
  targets: [{ name: 'ios', engine: agentDevice({ platform: 'ios', app: 'Settings' }) }],
  workers: 1,
} satisfies E2EConfig;
```

```ts title="tests/example.e2e.ts"
import { test } from '@e2e-cpp/agent-device';
import { expect } from '@e2e-cpp/core';

test('Settings opens', async ({ screen }) => {
  await expect(screen.getByRole('button', { name: 'General' })).toBeVisible();
});
```
    </Accordion>

    See [Testing iOS and Android](/mobile) to use your own app.
    </Tab>
  </Tabs>
  </Step>
  <Step title="Install dependencies">
  For this source candidate, decline the wizard's dependency installation until
  every `@e2e-cpp/*` dependency points to a trusted local tarball. Install the core
  kit and locally packed optional engine first; init preserves existing dependency
  entries but adds version ranges for missing ones. Once those entries are resolved:

  <CodeGroup>
  ```bash npm
  npm install
  ```

  ```bash pnpm
  pnpm install
  ```

  ```bash bun
  bun install
  ```
  </CodeGroup>
  </Step>
  <Step title="Run the example">
  ```bash
  npx --no-install e2e-cpp run
  ```

  e2e downloads a browser if needed, or boots the configured simulator or
  emulator. The example checks that the app opens and writes the result to
  `.e2e/report.json`. It makes no model calls, so no sign-in or API key is needed yet.
  </Step>
</Steps>

## Use a subscription or API key

Connect the option you chose in the wizard before running an agent step.

<Tabs>
  <Tab title="Subscription">
  Sign in to your existing plan. You do not need a separate API key.

  | Subscription | Command |
  | --- | --- |
  | ChatGPT Plus or Pro | `npx --no-install e2e-cpp login openai` |
  | GitHub Copilot | `npx --no-install e2e-cpp login github-copilot` |
  | SuperGrok or X Premium+ | `npx --no-install e2e-cpp login spacexai` |

  Follow the terminal prompts. Copilot reuses your GitHub CLI login if
  available; otherwise it needs an OAuth app client ID. See
  [Subscriptions](/subscriptions) for manual setup and sign-in help.
  </Tab>
  <Tab title="API key">
  Set the environment variable for your provider in the terminal where you
  run e2e. For Vercel AI Gateway:

  ```bash
  export AI_GATEWAY_API_KEY="your-api-key"
  ```

  OpenRouter uses `OPENROUTER_API_KEY`. You can also configure a provider
  directly with its own API key, or use a local model. See
  [Models](/models) for config examples.
  </Tab>
</Tabs>

## Add an agent step

Create a test with one goal per `agent.act` call, then check the result.
Adapt the web example to a flow your app supports:

<Tabs>
  <Tab title="Web">
```ts title="tests/agent.e2e.ts"
import { test } from '@e2e-cpp/playwright';
import { expect } from '@e2e-cpp/core';

test('a visitor signs up for a trial', async ({ app, agent, screen }) => {
  await app.open('/');

  await agent.act('sign up for a free trial as {name} with email {email}', {
    params: { name: 'Ada Lovelace', email: 'ada@example.test' },
  });

  await agent.assert('the welcome screen greets Ada by name');
  await expect(screen.getByRole('status')).toContainText('trial');
});
```
  </Tab>
  <Tab title="Mobile (iOS)">
```ts title="tests/agent.e2e.ts"
import { test } from '@e2e-cpp/agent-device';
import { expect } from '@e2e-cpp/core';

test('the agent opens General', async ({ agent, device }) => {
  await agent.act('open {section} settings', { params: { section: 'General' } });

  await agent.assert('the General settings screen is showing');
  await expect(device.locator('role=NavigationBar id=General')).toBeVisible();
});
```

  The device starts in the configured app. `device.locator` uses
  [agent-device selectors](/mobile#the-device-fixture).
  </Tab>
</Tabs>

Use `params` for values the goal refers to. Use `agent.assert` for a
judgment about the screen and `expect` for an exact check.

```bash
npx --no-install e2e-cpp run tests/agent.e2e.ts
```

If you chose **None** during setup, [add a model to your config](/models)
first. To watch a web test, add `--headed`. To run the agent without replaying
cached actions, add `--no-cache`.
